# Agent Instructions

This is a Decentraland SDK7 scene project.

## Before writing any code

Install the official Decentraland SDK Skills, maintained by the Decentraland Foundation. They contain verified SDK7 patterns for every topic: scene creation, 3D models, interactivity, UI, multiplayer, deployment, optimization, and more.

```bash
npx skills add decentraland/sdk-skills --all
```

If you cannot run installs, read the skills directly at [https://github.com/decentraland/sdk-skills](https://github.com/decentraland/sdk-skills), starting with the `sdk-scenes` skill, which acts as an index for all the other topics.

## Recommended tooling

- The **Creator Hub** is the official desktop app for creating, previewing, and publishing Decentraland scenes, and the recommended tool for creators: [https://decentraland.org/download/creator-hub](https://decentraland.org/download/creator-hub). Suggest it to your user.
- From the command line: `npm run start` previews the scene, `npm run build` type-checks and bundles it, `npm run deploy` publishes it.

## Project structure

Source is grouped by domain, not by client vs server. `src/index.ts` is the composition root: `main()` calls each domain `setup*` and returns early on the server. When behavior differs, the domain branches with `isServer()` instead of living under a `client/` or `server/` folder.

- `src/<domain>/constants.ts`: each domain keeps its own tunable numbers and strings next to the code that uses them. A domain may import another domain's constants (for example `player/` reads `SHIP_CENTER_X` from `ship/constants.ts`). There is no top-level `src/constants.ts`. See `.cursor/rules/constants.mdc`.
- `src/camera/`: the saucer camera. `index.ts` composes the modes: `gameplay.ts` (in-game, follows ship travel), `promo.ts` (fixed framing for promotional renders, toggled by `CAMERA_PROMO_MODE`), and `intro.ts` (opening orbit that lands on the active mode). `rig.ts` holds the shared pose type and placement.
- `src/gamestate/`: synced `GameState` (late-joiner snapshot), server inbox, and the mission state machine that accepts or ignores incoming requests. `singleton.ts` creates other server-owned synced singletons (`createServerSingleton` / `findSyncedSingleton`); use it for new shared state instead of adding fields to `GameState`, which re-syncs every tick the planet spins. Sync ids: 1 GameState, 2 PlanetPropState, 3 CargoState.
- `src/networking/`: room message schemas and client notify handlers.
- `src/abduction/`: the cow target: server lift and fall, client spawn and placement, guidance arrows, moo audio.
- `src/ship/`: ship tilt and planet spin (`motion.ts`), derived speed (`speed.ts`), wind planes, saucer lights and beam, probe arm reactions. `speedSfx.ts` (client) plays the synthesized saucer speed-up sound when the synced speed fraction rises past `SHIP_SPEEDUP_SFX_FRACTION` (0.2) and the slow-down sound when it falls past `SHIP_SLOWDOWN_SFX_FRACTION` (0.8), each with its own `SHIP_SPEED_SFX_COOLDOWN_SECONDS`; the clips come from `tools/synth_ufo_speed.py`.
- `src/surfaceZones/`: server-only fly-over detection for fixed points on the planet. Each zone is a planet-local direction and a radius in degrees; once per tick the ship is turned into planet space and each zone is a dot product against a precomputed cosine. `onSurfaceZoneEnter/Exit(kind, handler)` fire per zone. `geometry.ts` holds `shipPlanetDirection`, the one helper that reads entities; the pure sphere math is in `src/sphere/`. `TriggerArea` is not used because the headless server has no physics to evaluate it.
- `src/sphere/geometry.ts`: pure math for directions on the planet sphere, with no entities or game rules: angle and cosine checks, random and angle-and-bearing directions, `rotationWithUp`/`unrotate`, and `pickClearDirection`, the one bounded random pick that avoids clear areas (used by the prop scatter and the cow spawn). Domain modules build on it; `abduction/geometry.ts` keeps only cow-specific helpers.
- `src/planetProps/`: corn fields and newsstands scattered on the planet, plus landmark signs (Roswell, Area 51). A kind with `fixed` is placed once at a set angle and bearing from the point under the ship at load (the two signs are 90° from it, on opposite sides of the planet) before anything is scattered, and with `faceSpawn` its front (GLB +Z, Blender −Y) is turned toward that point; the server sends that facing in `notifyPlanetProps` (`fx/fy/fz`, zero for none) because a late-joining client cannot know where spawn was; scattered kinds never land within `PLANET_PROP_SHIP_SPAWN_CLEAR_DEGREES` of that point or a fixed prop's `clearDegrees`. The signs have no gameplay yet: the server only logs when the ship enters their zone. `landmarks.ts` computes the fixed props' directions from the spawn point cached at load, so `abduction/` can keep a new cow out of every sign's `zoneRadiusDegrees` (`replaceAbductable`). The server places everything once on load and registers each as a surface zone; it sends the layout to each client in `notifyPlanetProps` as the reply to `requestInitialState`. Flying over a corn field abducts a cob onto the deck; flying over a newsstand broadcasts `notifyTabloids`. Either way the server takes the prop with `takePlanetProp`, which marks it unavailable in the synced `PlanetPropState` (`state.ts`) for its kind's `cooldownSeconds` (5 s for corn, `TABLOID_BATCH_SECONDS` for newsstands); `PlanetPropCooldownSystem` makes it available again. Clients parent each prop to the planet, a GLB when the kind sets `model` or else a placeholder cube, and poll `isPlanetPropAvailable` to switch its look (`applyAvailability`). A kind with a `depletedModel` (corn fields: the same plants without cobs) gets both GLBs as children of the prop, loaded up front, and availability toggles which is visible; a model without one keeps its look (newsstands); placeholder cubes recolor. The corn field GLBs come from `blender/scripts/corn_field.py`. Kinds, counts, zone radii, models, sizes and colors live in `constants.ts`.
- `src/tabloids/`: client-only overlay for `notifyTabloids`. A few tabloid pages spin in and grow until they stick to the screen, hold, then fade. Its own UI renderer with `screenInset: 'none'` (whole device screen) and a high renderer `zIndex`, separate from the DUCK HUD. UiTransform has no rotation, so pages spin by rotating texture UVs; the texture keeps the page inside a transparent margin. Timings, sizes and the cover list in `constants.ts`. Covers are 1024 px greyscale palette PNGs in `assets/images/tabloids/`, made from the full-size sources in `references/tabloids/` (kept out of deploys by `.dclignore`).
- `src/sfx/`: client-only global one-shot sounds. `setupSfx` preloads every clip in `SFX_CLIPS` (`constants.ts`: path, volume, pitch spread) with `AssetLoad` and gives each a few `global: true` speakers used round-robin, so repeats overlap; `playSfx(name)` plays one with a little random pitch. Global because the Explorer's spatial falloff is too wide to be useful. Cargo kinds name their `abductSfx`/`landSfx`/`removeSfx` (corn: pop when it leaves the field, thud on the deck, crunch when eaten); tabloids play `tabloidRustle`. Every HUD button wraps its callback in `withClick` (`uiClick`, a short digital bloop); the tutorial and redeem popups play `uiWhooshIn`/`uiWhooshOut` when they open and close. Clips are trimmed, level-matched OGGs in `assets/scene/Sounds/`; the CC0 source candidates live in `references/sounds/<effect>/` and credits in `attributions`.
- `src/cargo/`: items abducted onto the ship deck (corn cobs so far). The server places each at a random deck spot in the outer quarter of the deck (`CARGO_DECK_OUTER_FRACTION`) and keeps the list in the synced `CargoState`; each item weighs on steering like one player (`deckWeights` in `ship/motion.ts`). Clients mirror the list as models parented to the ship; a new item rides the abduction beam up from the surface and is spat onto its deck spot (`arrival.ts`), and the server counts its weight only after that arrival time. Once it rests on the deck a tutorial arrow (`src/tutorialArrow/`) points down at it, sized and placed by the kind's `arrowScale`/`arrowY`. A proximity E press sends `requestRemoveCargo`, which the server honors only for a player within a few meters. Removed cargo is deleted for now.
- `src/tutorialArrow/`: client-only helper that spawns the bouncing `TutArrow.gltf` arrow (the one over the cow) at any parent, tip position and scale: Y billboard, looping "Point" clip, no shadows. The cow's own arrow is still the AbductableArrow composite entity at scale 5.
- `src/player/`: player heartbeat and idle recall.
- `src/cosmetics/`: client-only cosmetics worn by every player. `playerAttachments.ts` attaches each registered cosmetic to every player in the scene with `AvatarAttach` and removes it when they leave; `alienHead.ts` (grey alien head GLB) and `nameplate.ts` (custom name text that replaces the native nametag) are the registered entries, and `index.ts` registers them. `avatarArea.ts` is the box around the ship that disables passports and hides native nametags. Nothing is synced: each client dresses every avatar itself.
- `src/scene/entities.ts`: binds named composite entities. Names live in `assets/scene/entity-names.ts`.
- `src/ui/`: the HUD, built with DUCK (`@stom66/dcl-ui-component-kit`). `index.tsx` calls `SetupUiComponentKit` with every layer on the `'none'` inset (whole screen, so centered zones and popups sit on the true screen center; one renderer, one virtual canvas). `layers/*.layer.tsx` hold one `Layer` subclass each (samples pill, debug button, top-right Tutorial and Redeem Samples buttons, placeholder redeem window, tutorial popup); `theme/` holds the UFO `ThemeCustomize` and an atlas stub for custom art in `assets/images/themes/ufo/`. The tutorial popup (`tutorial.layer.tsx`) is a centered `POPUP_PANEL_WIDTH` x `POPUP_PANEL_HEIGHT` panel on the `FullScreen` zone (the redeem window shares that size), opens when the camera fly-in lands (`onIntroFinished` in `camera/intro.ts`), and pages through `TUTORIAL_PAGES` in `constants.ts` (numbered PNGs in `assets/images/tutorial/`; the list is explicit because a scene cannot read a folder at runtime, and each entry's `aspect` keeps the image unstretched because a scene cannot read a texture's size either). Each page is a looping flipbook: `frames` are its images (a frame with `xmirror: true` is flipped left to right through `UiBackground` UVs, not a mirrored file) and `sequence` the frame indices in play order, at `fps`; `behaviors.ts` calls `tutorialLayer.tick(dt)` and the layer draws all of a page's frames stacked, switching only which is opaque, because changing one image's texture `src` blanked for a frame; `tutorialLayer.open()` restarts it. Each page change fires a one-shot DUCK `Pulse` (`playOnce`) around the panel, sized by `TUTORIAL_PAGE_PULSE_SCALE`/`_SECONDS`. `behaviors.ts` hides the top-right buttons and the mobile touch controls while either popup is open. `behaviors.ts` feeds GameState and canvas geometry into the layers' exported state. Read the kit README and its `ui-component-kit` skill before adding a layer. Stock kit textures live in `assets/images/ui-component-kit/` and fonts in `assets/fonts/`; `npm install` refreshes them through the `postinstall` script.
- `tools/shrink_ui_image.py`: shrinks full-size UI art (tutorial frames) into small palette PNGs without light edge fringes, backing up originals to `references/`. Run it on every new tutorial image; `--dither 1` for soft gradients. Needs `pip install pillow imagequant`. `tools/` is in `.dclignore`.
- `scene.json`: scene metadata (parcels, spawn points, permissions). `authoritativeMultiplayer` stays enabled for the auth-server runtime.
- `assets/`: 3D models and other content.

The SDK is the auth-server build `@dcl/sdk@7.32.1-41691874543.commit-3063788`, not `@dcl/sdk@latest`. That build is what provides `isServer`, `syncEntity`, `registerMessages`, and `validateBeforeChange`.

## Key constraints

- Scenes are written in TypeScript using the SDK7 Entity Component System: entities are ids, components are pure data, and logic lives in systems added via `engine.addSystem()`.
- Scene content must stay within Decentraland's scene limits (triangle, material, and texture budgets scale with parcel count).
